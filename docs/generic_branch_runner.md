# Generic MD-DMS branch runner

## Why this file exists

`run_mddms_pilot.py` is retained as the historical low-level generator that created the original Paper 2 / Paper 3 style LAMMPS inputs. `paper2_revision_runner.py` is also retained unchanged so its original commands and provenance remain reproducible.

The new `scripts/run/mddms_branch_runner.py` is a thin reusable layer. It imports the tested Paper-2 branching/checkpoint helpers instead of copying their implementation. This gives later campaigns more flexibility without replacing the historical machinery.

## Compatibility model

The default Stage-03 start mode is:

```text
data-recreate-velocities
```

This preserves the historical semantics: Stage 03 reads `02_after_equilibrate_nvt.data`, resets the deformation clock, and creates a new 300 K velocity field with the same historical generator rule.

Therefore an old-style run can be regenerated with the new runner by supplying the same composition, density, seed, timestep, temperature, strain amplitude, thermostat/barostat parameters, period, cycle count, sampling cadence, model, and parent Stage-02 state.

The old `paper2_revision_runner.py` remains available and is not redirected through the new code.

## New start mode

The optional mode

```text
restart-preserve-velocities
```

replaces only the Stage-03 initialization semantics:

```text
read_data 02_after_equilibrate_nvt.data
velocity all create ...
```

becomes

```text
read_restart 02_after_equilibrate_nvt.restart
# no velocity recreation
```

The MD-DMS timestep, strain law, thermostat, deformation rule, period, cycle count and stress sampling remain those generated by `run_mddms_pilot.py`.

This is intended as a protocol control, not as a silent change to historical production.

## Preparation controls

The generic `prepare` command passes preparation overrides to the historical generator:

```text
--melt-ps
--quench-rate-K-per-ps
--relax-ps
--equilibrate-ps
```

The generated `metadata.json` remains the authoritative record of the effective preset and command line.

## Checkpoint and provenance behavior

Stage-03 branches retain the existing checkpoint/resume design. Each child run has a new directory and does not overwrite its parent. The branch copies the Stage-02 data/restart and parent metadata, records the requested protocol, preserves the original generated Stage-03 input, stores the effective uncheckpointed input, writes a checkpointed input and resume input, and records the selected start mode.

## Regression tests

`tests/test_mddms_branch_runner.py` contains small standard-library tests for:

- byte preservation of the historical Stage-03 input before checkpoint patching;
- the restart-preserving transformation;
- propagation of composition, strain amplitude, thermostat damping and period into the historical generator command.

Run from the repository root with:

```bash
python -m unittest tests/test_mddms_branch_runner.py -v
```

A full compute-node validation should additionally generate one old-style branch with both runners and diff the scientifically relevant LAMMPS commands before production control calculations are launched.
